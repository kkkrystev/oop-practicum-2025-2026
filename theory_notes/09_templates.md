# Тема 09 : Шаблони

## 1. Templates

Template (шаблон) е механизъм в C++, който ни позволява да пишем generic класове или функции. Това ни позволява да напишем код, който работи за произволен тип данни без да го пишем експлицитно за всеки тип. 

Шаблонът не е функция или клас сам по себе си. Шаблоните са инструкции към компилатора за това как той да генерира код за конкретен тип. Генерирането става при компилация (*compile-time*), когато шаблонът се използва с конкретен тип – процес, наречен *инстанциране*.

*Нека дефинираме един function template. Ще използваме примера, за да въведем няколко понятия, които ще използваме.*

```c++
template <typename T>
void foo(T value) {
	std::cout << value << '\n';
}
```

В горния пример `foo` не е "истинска" функция. Той е шаблон за това как компилаторът да генерира функция на име `foo`, която може да работи с произволен тип. *Тук има малко ограничение, което ще коментираме по-долу.* 

`typename T` наричаме *template параметър*. 
- `typename` оказва какъв вид template параметър дефинираме - в случаят е *type template parameter*.
	- Еквивалентен запис би бил `class T`.
- `T` е името на съответния *template параметър*. 
	- В рамките на шаблона ние можем да използваме име, за да абстрахираме типа данни, който ще бъде използван.
	- *Не е е задължително да се казва `T`. На практика можем да го кръстим, както искаме.*

Важно е да уточним, че шаблоните налагат ограничения върху типовете, които можем да използваме, тъй като компилаторът изисква те да поддържат всички операции, използвани в шаблонната дефиниция, без гаранция за автоматични преобразувания или липсващи поддържани поведенчески свойства.

```c++
template <typename T>
T add(T a, T b) {
    return a + b;
}

struct A {};

int main() {
    add<int>(3, 4);        // OK
    //add<A>(A{}, A{});    // ERROR (няма operator+ за A)
}
```

Запомнете, че чрез употребата на шаблони осъществяваме **compile-time polymorphism**. *За полиморфизъм ще си говороим повече по-късно в курса.*

## 2. Видове template parameters и още

Templates са параметризирани от един или повече template параметри. Имаме три вида:
#### 1. type template parameters

Това са параметри, които представляват типове. Когато се дефинира шаблон с такъв параметър, ние казваме на компилатора: „тук ще има някакъв тип, който ще бъде уточнен по-късно“. В тялото на шаблона този тип се използва като напълно реален тип - за декларация на променливи, параметри, връщани стойности и т.н. При инстанциране компилаторът просто замества параметъра с конкретния тип и генерира съответния код.
#### 2. non-type template parameters

Тук параметърът не е тип, а конкретна стойност, известна по време на компилация. Ограничението е, че тези стойности трябва да са такива, които могат да съществуват на ниво компилация - например цели числа, указатели, булеви стойности и други константни изрази.

*Нека разгледаме следния пример.* 

```c++
template <typename T, int N>
class Array {
	T data[N];
};

int main() {
	Array<int, 10> arr1;
	Array<int, 20> arr2;
}
```

Важни наблюдения:
1. Забележете, че можем да декларираме `T data[]` с размер `N`, защото променливата `N` е *оценена (evaluated)* по време на компилация.  
2. Тази стойност `N` става част от самия тип на инстанцията - в примера `arr1` и `arr2` са различни типове, защото имат различни стойности за `N`.
#### 3. template template parameters

Тук параметърът на шаблона сам по себе си е шаблон. Това означава, че подаваме не конкретен тип, а „шаблон за тип“. Този механизъм се използва, когато искаме да пишем код, който работи с цели семейства от типове, генерирани по една и съща схема.

*Най-вероятно няма да се ползват в рамките на курса. Но, хей, нищо не се знае ;-)*

```c++
template <typename T>
class Box { 
public:
	T value;
}; 

template <template <typename> class Container>
class Wrapper {
public:
	Container<int> data;
};

int main() {
	Wrapper<Box<int>> w;
}
```

Можем да имем **template параметри по подразбиране**. *Пример:*

```c++
template <typename T=int, int N=10>
void bar(T val) { 
	// do something...
}
```

## 3. Type deduction and when it fails

Type deduction е процесът, при който компилаторът автоматично извежда template параметрите от подадените аргументи при извикване на шаблон.

Той се проваля, когато няма достатъчно информация (например няма аргументи), когато типовете са несъвместими и не може да се изведе един общ тип, или когато извеждането би изисквало неявни преобразувания, които deduction не допуска.

```c++
template <typename T>
T add(T a, T b) {
    return a + b;
}

int main() {
    add(1, 2);       // OK T = int
    // add(1, 2.5);  // ERROR няма еднозначен T
}
```

## 4. Шаблони и разделна компилация

Шаблоните не се превръщат директно в машинен код при дефиницията си. Компилаторът генерира конкретна реализация (инстанциация) едва когато шаблонът бъде използван с конкретен тип.

За да извърши тази инстанциация, компилаторът трябва да има достъп до пълната дефиниция на шаблона в момента на компилация. Ако дефиницията не е видима, той не може да генерира необходимия код и възниква грешка.

Тук е съществената разлика между шаблонния и обикновения C++ код.

При обикновените класове и функции, когато `.cpp` файл включи (`#include`) `.h` файл, компилаторът допуска декларации без тела, защото очаква реализациите да бъдат намерени на етапа на свързване (linking). Всеки `.cpp` се компилира отделно до обектен файл, а после linker-ът ги обединява и резолвира символите.

При шаблоните този модел не работи. Те не представляват конкретен код, а описание как да бъде генериран код. Всяка употреба на шаблона с нов тип изисква компилаторът да създаде съответната инстанциация в конкретния translation unit. Това означава, че той не може да отложи тази работа за linker-а и не може да разчита на дефиниция, намираща се в друг `.cpp` файл. Ако дефиницията е скрита (например е само в `.cpp`), тя няма да бъде видима в момента на използване и ще се получи грешка.

Оттук следва практическото правило: дефинициите на шаблони трябва да бъдат достъпни навсякъде, където се използват. Поради тази причина те обикновено се поставят в header файлове. Често се използва разширение като `.hpp`, за да се подчертае, че файлът съдържа не само декларации, а и пълни дефиниции на шаблони.

Съществува и вариант с разделяне на декларация и дефиниция (например `.h` + `.tpp`), като `.tpp` файлът се включва в края на header-а чрез `#include`. Това технически запазва структурата, но отново гарантира, че дефиницията е видима при компилация. При писане на класове имаме две опции - да дефинираме функцията или в тялото на класа, или извън тялото.

```c++
template <typename T>
class MyClass {
public:
	void foo() {
		// do something...
	}
	
	void bar();
}

template <typename T>
void MyClass<T>::bar() {
	// do something...
}
```

Допълнително важи и правилото One Definition Rule (ODR) — всяка функция или клас трябва да има точно една дефиниция в програмата. При шаблоните обаче различните translation unit-и могат да генерират свои инстанциации. Това е позволено, защото те са еднакви и linker-ът ги обединява. Проблемът не е в множествените инстанциации, а в липсата на достъп до дефиницията там, където е необходима.

## 5. Темплейтна специализация

Понякога се налага да дефинираме специално поведение на шаблон за определен тип или за група типове. Общата дефиниция на шаблона се нарича _primary template_.

Съществуват два основни вида специализация.

Пълната специализация (_explicit specialization_) задава изцяло нова имплементация за конкретен тип. Тази специализация напълно замества _primary template_ за съответния тип и не използва нищо от него.

Пример: *Explicit specialization на function template*

```c++
template <typename T>  
void foo(T value) {  
	// do something...  
}

// explicit specialization за int  
template <>  
void foo<int>(int value) {  
	// do something specific... 
}
```

Пример: *Explicit specialization на метод от class template*

```c++
template <typename T>  
class Box {  
public:  
	void foo();
};  

template <typename T>
void Box<T>::foo() {  
		// do something...
	}  

// explicit specialization на метода foo за Box<int>  
template <>  
void Box<int>::foo() {  
	// do someting specific...  
}
```

Частичната специализация (_partial specialization_) позволява да се дефинира поведение за цял клас от типове, а не за един конкретен. Например можем да кажем „за всички указатели“ или „за всички масиви“. Така се модифицира поведението само за тази категория типове, докато останалите продължават да използват _primary template_.

Важно ограничение е, че частична специализация е позволена само за класове (и структури), но не и за функции.

```c++
// Primary template
template <typename T> 
class MyClass { };

// Пълна специализация за int
template <>class MyClass<int> { };

// Частична специализация за указатели
template <typename T>
class MyClass<T*> { };
```

При функциите ситуацията е различна. Функционални шаблони не могат да бъдат частично специализирани. Вместо това се използва _overloading_ (претоварване), което често постига сходен ефект.

```c++
// Общ шаблон (аналог на primary template)  
template <typename T>  
void func(T value) {  
	cout << "Generic template\n";  
}  
  
// "По-специализиран" вариант за указатели (чрез overloading)  
template <typename T>  
void func(T* value) {  
	cout << "Pointer version\n";  
}  
  
// Обикновена (не-шаблонна) функция за конкретен тип  
void func(int value) {  
	cout << "Non-template int version\n";  
}
```

При избора коя функция да бъде извикана, компилаторът следва правила за приоритет. Тези правила интуитивно могат да се обобщят така:

- обикновените (не-шаблонни) функции имат най-висок приоритет, ако са подходящи;
- при шаблоните се избира най-специализираният вариант;
- primary template се използва само ако няма по-специфичен съвпадащ вариант.
